# MC-ModSync 玩家使用说明

> 你只需要做一件事：**关掉游戏 → 双击「更新mod」→ 等它跑完 → 手动打开启动器进服。**

---

## 1. 更新前的准备

1. **完全退出 Minecraft**（含启动器里的游戏进程）。程序会检测有没有 **Minecraft 客户端**
   正在运行，检测到会直接退出并提示（退出码 **3**），不会改动任何文件。
   （机上有其它 Java 程序——如 IDEA、另一个 Java 应用、同机开的 MC 服务端——**不会**被误拦。）
2. 确认网络可用（需访问云端清单与 CDN）。

---

## 2. 怎么更新

1. 把发放给你的整个目录（含 `更新mod.bat`、`更新mod.sh`、`_updater/`）放到**整合包根目录**
   （即与 `.minecraft`、启动器配置同级，`_updater/` 与 `更新mod.bat` 必须同级）。
2. **双击 `更新mod.bat`**（Linux/macOS 执行 `sh 更新mod.sh`）。
3. 观察窗口输出，会显示当前阶段、要更新几个文件、总大小、以及一个纯文本进度条：

   ```
   进度 [########--------------------]  28%  2/7 个文件  12.4/44.1 MiB
   ```

4. 结束后会显示：
   - 成功：`=== 更新完成，请手动启动 PCL2 或 HMCL ===`
   - 失败：`=== 更新失败，退出码 N，日志见 _updater\logs\ ===`
5. 窗口默认会停住等你按任意键（方便看结果）；若加了 `--no-pause` 参数则不停留。
6. **手动打开 PCL2 / HMCL 进服**。程序不会自动启动任何启动器。

---

## 3. 退出码含义表

| 码 | 含义 | 你该做什么 |
|---|---|---|
| 0 | 成功（含「已是最新、无需更新」） | 直接进游戏 |
| 1 | 通用失败（含版本回退被策略拒绝、`verify` 发现差异） | 看日志；把日志发给管理员 |
| 2 | 验签失败 / 公钥不匹配 | 可能是配置或发布异常，**别进服**，立即联系管理员 |
| 3 | 游戏运行中 | 完全退出游戏后重试 |
| 4 | 磁盘空间不足 | 清理磁盘空间后重试 |
| 5 | 网络不可达 / 下载重试耗尽 | 检查网络、代理后重试 |
| 6 | 清单版本过新（更新器过旧） | 需要管理员发新的 `_updater`，你重装后再更新 |
| 7 | `packId` 不匹配 | 配置串包了，联系管理员 |
| 10 | 锁冲突（已有更新在运行） | 关掉另一个更新窗口，稍后重试 |
| 13 | 路径非法 | 联系管理员（清单里有非法路径） |
| 99 | 仅测试用故障注入 | 正常发布不会出现；出现请反馈 |

> 说明：`11 / 14 / 15 / 18 / 19` 是**服务端**内部错误码，玩家端不会出现。
> 玩家端在「没有可回滚备份」或「已回滚过」时统一返回 **1**。

---

## 4. 版本回退时会看到什么

如果管理员误发了旧版本，你更新时会看到醒目的多行警告：

```
================================================================
警告：检测到版本回退 —— 本地已同步 1.0.5，云端最新为 1.0.4
警告：这通常是发布端误操作；如非预期请立即联系管理员。
================================================================
```

默认行为是**继续更新**（回到云端指定版本）；管理员也可能下发带 `--no-downgrade` 的入口脚本，
那样会以退出码 **1** 终止、不改动你的文件。

---

## 5. 日志在哪

- `_updater/logs/updater-<日期>.log`（UTF-8）
- 日志内含：每个文件的 sha256、决策（新增/更新/改名复用/删除/跳过）、HTTP 状态码、警告
- 出错时窗口最后一行会直接打印日志路径

---

## 6. 常见问题

**双击后窗口一闪而过？**
窗口默认会 `pause`。若仍一闪而过，说明入口脚本被改成了 `--no-pause`，或杀软拦截了 exe。
请用命令行手动运行 `更新mod.bat` 查看输出。

**杀软/安全软件报警拦截？**
会有这种误报。请先把 `_updater\mcmodsync.exe` 加入信任。若被删除，可直接用纯 Python 兜底（无需 exe）：

```bash
# 需系统已安装 Python 3.10+
python "_updater/mcmodsync.py" sync --target "<整合包根目录>"
```

**提示「检测到 Minecraft 客户端正在运行」？**
彻底退出游戏（含启动器里正在跑的游戏进程、另开的整合包实例）后重试。
同机只开着 IDE / 其它 Java 程序 / MC 服务端，不会触发这条提示。

**能装 mod 到一半失败吗？**
不会把半成品留在 `mods/` 里：下载先落暂存区并逐个校验 sha256，通过后才原子替换；
替换/删除前会备份到 `_updater/backup/<时间戳>/`，可用 `rollback` 还原。

**想自己回滚到上一版？**
命令行执行（一般由管理员指导）：

```bash
_updater\mcmodsync.exe rollback --target "<整合包根目录>"
_updater\mcmodsync.exe verify   --target "<整合包根目录>"   # 只检查不修改
_updater\mcmodsync.exe doctor   --target "<整合包根目录>"   # 自检
```

**我只想确认自己是否和服务器一致？**
运行 `verify`：完全一致退出码 0，有差异退出码 1，并会列出「缺失 / 损坏 / 多余（自己装的）/ 待删除」。
注意：默认**宽松模式**不会删除你自己额外安装的 jar；管理员若启用严格模式（`--strict`），
这些自装 jar 会被备份后删除。
