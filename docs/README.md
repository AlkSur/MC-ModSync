# MC-ModSync

Minecraft NeoForge 服务器 mods 增量同步系统。三个脚本各管一段：

| 脚本 | 运行在哪 | 干什么 |
| --- | --- | --- |
| A（OP 端） | OP 的电脑 | 从 Modrinth/CurseForge 拉 mod、推送到服务器、发布到对象存储 |
| B（服务端） | MC 服务器 | 被 A 远程调用，把变更应用进 mods/ 目录，自动备份、可回滚 |
| C（玩家端） | 玩家电脑 | 双击一下，从对象存储增量下载变更的 mod |

## 它是怎么工作的（轻度版）

1. OP 在自己电脑上维护两个文件夹：`server-mods/`（服务端 mod）和 `client-mods/`（客户端 mod）。两者**本来就不同**——客户端有 JEI、优化、光影等纯客户端 mod。
2. OP 跑一条命令把服务端 mod 推到 MC 服务器。服务器上的 B 脚本会先**备份旧文件**，再应用变更，出问题可以一键回滚。
3. OP **手动重启 MC 服务器**，看日志确认能正常启动（出现 `Done (`）。确认没问题后，再跑一条命令把客户端 mod 发布到对象存储。
4. 玩家双击"更新mod"，脚本只下载**有变化的文件**（不是全量），替换完成后玩家自己打开 PCL2/HMCL 启动游戏。

关键保障：

- **失败不上传**：服务端没验证成功之前，玩家那边什么都不会变。
- **只下变更**：整合包几百 MB，每次更新通常只下几十 MB。
- **可回滚**：服务端和玩家端都有自动备份，随时可以退回到上一版。
- **防篡改**：发布内容带数字签名，玩家端会验签，被篡改的文件不会被应用。
