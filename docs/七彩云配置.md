### 步骤5 偏差详述（不达标项）

现象:

- 匿名 `GET https://s3.7caiyun.com/<bucket>/?list-type=2` → **HTTP 200**，返回 `ListBucketResult`，含 `KeyCount` 与实际对象键。
- 匿名 `GET https://s3.7caiyun.com/<bucket>/?prefix=t00list/`（V1）→ **HTTP 200**，列出键 `t00list/secret-a.txt`。
- 匿名 `GET https://s3.7caiyun.com/<bucket>`（裸桶根、无查询参数）→ HTTP 403 AccessDenied。
- 匿名经 CDN 域名列举 → HTTP 404（CDN 不承载 List 操作）。

影响:

- 计划的「随机前缀」保密性被削弱: 攻击者可先列举顶层前缀、再逐层列举，从而发现随机前缀与全部对象键。
- 由于桶本身公开读，被列举内容（清单、blob）本就可公开读取；签名（Ed25519）仍是完整性与真实性主控。故**这是加固/保密性问题，非功能性阻断**，但与计划 [3.13] 及 T-00 步骤5 的「不可列举」硬约束不符。

建议处置（三选一，交需求方决策）:

1. **主账号在控制台为该桶设置 Bucket Policy，显式拒绝匿名 `s3:ListBucket`**（推荐；实测用的子账号仅有对象级权限，无法自行改策略）。修改后重跑 `tools/t00_verify_7caiyun.py` 应 8/8 通过。
2. 接受该项偏差（认可「公开读 + 随机前缀 + 签名」的既有安全模型），在计划中记录降级说明后继续。
3. 触发分支 B-03，更换服务商。

## 4. 与 MinIO 的差异记录（步骤8）

| 维度 | MinIO（本地测试用） | 七彩云（生产） |
| --- | --- | --- |
| 寻址 | path-style / virtual-host 均可 | 均可，推荐 path-style |
| Region 取值 | 任意（`us-east-1` 常用） | 必须为 `us-west`（错误响应回显 Region 校验） |
| Cache-Control | 原样保留 | 原样保留（三类均一致） |
| 匿名读 | 取决于桶策略，默认私有 | 公开读桶可匿名 GET |
| 匿名列举 | 默认私有桶**拒绝**（403） | 公开桶**允许**（200，V2 与 V1-with-prefix；裸根 V1 为 403） |
| 缺失对象 | 404 NoSuchKey | 404（head 回 404） |
| 匿名错误码 | 403 AccessDenied | 403 AccessDenied（XML `<Error><Code>AccessDenied</Code>`） |
| 对外分发 | 无内置 CDN，需自建 | 内置 CDN 域名 `<bucket>.cdn.7caiyun.com`，HTTPS |

> 对 T-20（`storage/s3.py`）的影响: 按 T-00 结论配置 `endpoint_url=https://s3.7caiyun.com`、`region=us-west`、`addressing_style=path`；匿名列举差异仅影响安全加固，不影响 S3 读写 API 行为。

## 5. 结论

- 除「不可列举」外，七彩云满足 MC-ModSync 发布链路对 S3 兼容性、缓存头、HTTPS、匿名读与子账号四动作的全部要求。
- 步骤5 偏差已按 T-00 失败处理上报需求方，等待第 3 节处置决策；在决策前 T-00 保持 blocked。
