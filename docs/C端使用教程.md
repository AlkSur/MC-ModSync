# C端使用教程（玩家侧）

你是玩家。整个更新过程只有一步：**双击"更新mod"**。

## 〇、你需要哪些文件（玩家端包内容）

压缩包解压后是这些，**一个都不能少**：

```
<游戏实例目录>\
├── mods\                    ← 你原有的 mod 文件夹（判断"放对了没"就看它在不在同级）
├── 更新mod.bat              ← Windows：双击这个
├── 更新mod.sh               ← Linux / macOS：运行这个
├── SHA256SUMS.txt           ← 校验清单（可选，用来确认文件没损坏）
└── _updater\                ← 更新器本体，整个文件夹要有
    ├── config.json          ← 服主已经填好（CDN 地址 + 包标识 + 公钥），不用你改
    ├── mcmodsync.exe        ← Windows 主程序
    └── mcmodsync.py         ← 纯 Python 兜底（exe 被杀软删了时用）
```

放置规则只有一条：**`更新mod.bat` 和 `_updater\` 要和 `mods\` 在同一层**。

- 常见目录：`.minecraft\`（没有版本隔离）
- 开了版本隔离：`.minecraft\versions\<版本号>\`

`更新mod.bat` 会把它**自己所在的目录**当作游戏目录，所以你把它放在哪一层，它就在哪一层的 `mods\` 里干活。**不要放进 `mods\` 里面**。

**你不需要配置任何东西**：`_updater\config.json` 里的地址与公钥由服主打包时写入，直接可用。也不需要手动下载任何 mod——双击后脚本自己去下载。

### 手上没有现成压缩包？

玩家端**必须由服主生成后分发**，不要试图从源码里手工拼——原因是 `_updater\config.json` 里写着你这台服务器的专属地址和公钥，拼错了更新器会拒绝工作（退出码 2 或 7）。

**服主侧：生成玩家端包**

```powershell
# 1) 先生成玩家端文件（会渲染 config.json）
mcmodsync package-client
# 产物在 dist\client-package\

# 2) 再打成压缩包（同时也会生成 A 端、B 端的包）
python tools\make_release.py
# 产物在 dist\release\MC-ModSync-C端-玩家更新器-v<版本>.zip
```

**玩家侧：拿到包之后**

解压 → 把里面全部内容放进游戏实例目录（与 `mods\` 同级）→ 双击 `更新mod.bat`。不需要任何配置。

### 关于"版本号"

玩家端会看到两个版本号，含义不同：

| 版本 | 是什么 | 谁决定 |
| --- | --- | --- |
| 更新器版本（如 2.1.2） | 更新器程序本身的版本，三端统一 | 服主，随程序发布 |
| 内容清单版本（如 1.0.1） | 已发布的 mod 清单版本 | 服主，每次 `publish-client` 发布时自动 +1 |

更新器每次都会核对实际 `mods/` 文件的 SHA-256；即使内容清单版本没变，缺失或损坏的 mod 也会重新下载。更新器版本低到不能兼容时才会提示"联系服主拿新版"（退出码 6）。

更新后还会再次核对完整清单，复核通过才记录成功。窗口会打印实际 mods 目录、云端内容版本和文件数；如果启动器开启了版本隔离，务必确认这里打印的目录就是该版本实际使用的 mods 目录。

文件改名不会改变内容哈希。对于「文件名和内容都变了」的旧版本，更新器会读取已校验的新 jar 与本地 jar 的 modId，备份并清理同一模组的旧副本；不同 modId 的自装模组保留。这适用于 NeoForge、Forge、Fabric 和 Quilt 的常规根元数据，不要求重新发布旧清单。无法读取 modId 的库或特殊组件仍按内容哈希和历史文件名处理，不能保证识别被任意改名的旧版本。一个 jar 同时包含整合包模组和其他模组时会停止并提示人工处理。

默认同时下载 8 个文件，总连接上限 32；Modrinth / CurseForge 直链的大文件也会分片下载。可在 `_updater/config.json` 中调整 `downloadConcurrency`（1～32）和 `downloadConnections`（1～64）；连接预算由全部文件共享。源站不支持分片时回退单连接，平台失败时仍回落对象存储。2.2.1 起，两个大文件在默认预算下可各使用最多 16 条连接，单个大文件最多 32 条；临时失败仅续传重试对应分块，只有源站不支持可靠 Range 时才回退单连接。详细日志会记录启动的连接数和回退原因。增加并发不保证跨境网络一定变快。

## 一、怎么更新

从 2.2.0 起，双击入口会先检查更新器程序：发现新版时先下载、验签和校验文件，退出旧程序后由新版安装，再自动继续同步 mod。更新器和 mod 使用独立版本号；更新程序不会覆盖本地配置、状态或 mod 备份。

更早版本需要先手动覆盖一次新的 `更新mod.bat` / `更新mod.sh` 和 `_updater` 中的程序文件，保留原来的 `config.json`、`state.json`、`backup/`。只替换 exe 而保留旧启动脚本，无法自动完成切换。

服主没有发布程序更新（`updater.json` 不存在）或检查时暂时无法联网，会继续用当前程序检查 mod。已发现新版但下载或验证失败时会停止，避免在需要升级时继续使用旧程序；安装中途失败会尝试恢复旧程序并提示失败。

1. （可选）关掉游戏。**不关也能更新**——游戏只在启动时读一次 `mods/`，
   更新写入磁盘后重启游戏即生效；只是万一某个 jar 正被占用会提示你关掉游戏重试。
2. 双击游戏目录里的 **`更新mod.bat`**（Windows）或 **`更新mod.sh`**（Linux/Mac）。
3. 等它跑完。它只会下载有变化的 mod，通常几十 MB，很快。
4. 看到 `=== 更新完成，请手动启动 PCL2 或 HMCL ===` → 自己打开启动器，正常进游戏。

就这些。它不会替你打开启动器，也不会动你的存档、配置和截图。

## 二、它会动什么、不动什么

| 会动 | 不会动 |
| --- | --- |
| `mods/` 文件夹里的 `.jar`（增、删、换；含同 modId 的旧副本） | 不同 modId 的自装 mod（默认保留） |
| | `.jar.disabled` 结尾的文件（完全不碰） |
| | mods 以外的任何东西（存档、配置、光影包等） |

## 三、看到失败了怎么办

窗口里会显示一个**退出码**和日志位置。对着下表看：

| 退出码 | 意思 | 你该怎么办 |
| --- | --- | --- |
| 5 | 网络问题（含 HTTPS 证书校验失败） | 见下面「连不上服务器」一节 |
| 4 | 磁盘空间不足 | 清理磁盘后重新双击 |
| 2 | 文件被篡改/验签失败 | 别反复试，联系服主 |
| 6 | 你的更新器太旧了 | 联系服主拿新版更新器 |
| 7 | 配置不对（包标识不匹配） | 联系服主 |
| 1 | 写入/删除失败（提示里会写明是哪个文件） | 按提示关闭游戏（或退出占用的杀软/同步盘）后重新双击 |

> 更新器**不会**因为游戏开着而拒绝执行（旧版本会，退出码 3 已停用）：游戏只在启动时读一次
> `mods/`，磁盘上的 jar 更新后重启游戏才生效。

### 连不上服务器（退出码 5）

如果窗口里出现类似这样的提示：

```
无法建立安全连接（HTTPS 证书校验失败）
    目标主机: server-mods-xxxx.cdn.7caiyun.com
    本机时间: 2026-09-20 22:32:59
    失败原因: certificate has expired
```

这**不是服主的问题，也不是更新器坏了**，而是你这台电脑判定"服务器的证书无效"。按顺序排查：

**1. 先看系统时间（最常见原因）**
右下角时间 → 右键「调整日期/时间」→ 打开**自动设置时间**。时间偏差会让证书被判定成"已过期"或"还没生效"。

**2. 更新系统根证书**
Windows 设置 → 更新和安全 → 检查更新（装完重启）。老系统缺新证书会连不上大部分 HTTPS 网站。

**3. 检查杀毒软件 / 公司代理**
有些安全软件会开启"HTTPS 扫描"，用自己的证书拦截流量，那个证书过期就会报同样错误。临时关闭后重试。

**自测方法**：把窗口里提示的那个地址复制到浏览器打开——

- 浏览器也报证书错误 → 确认是上面三种机器级问题
- 浏览器能正常打开 → 把窗口内容（或 `_updater\logs\` 里的日志）发给服主

> 说明：更新器**不会**为了绕过这个问题而忽略证书校验。跳过校验等于任何人都能替换你的 mod，所以这里宁可报错。
| 10 | 已经有一个更新在跑 | 等它结束，别重复双击 |

详细日志在 `_updater/logs/` 文件夹里，找服主排查时把这个文件夹发给他。

## 四、想回到上一个版本

更新后进不去游戏？双击改成：

```
更新mod.bat rollback
```

（或在终端里运行 `_updater/mcmodsync.exe rollback`）

它会用自动备份把 mods 恢复到更新前的样子。恢复后再联系服主说明情况。

## 五、玩家常见问题

- **我自己装的 mod 会被删吗？** 默认不会。只有服主明确要求"严格模式"时，不在官方清单里的 mod 才会被移除——而且也是被备份而不是直接删除，可以找回。
- **每次都要全量重下吗？** 不用。只有变化的文件会下载，没变的原样保留。
- **版本变旧了（服主回退了）会怎样？** 屏幕会有明显警告，默认照常同步回旧版，这是正常的。
- **下载速度怎么样？** 2MB 以上的 mod 会自动**多线程分片下载**（单文件最多 32 条连接，仍受总连接预算限制）；小文件走单连接（省掉多余请求）。速度主要由你的宽带和下载节点决定。
- **Windows 报毒？** 单文件 exe 容易被误报。可以让服主给你 `.py` 版本，或核对包里的 `SHA256SUMS.txt`。
