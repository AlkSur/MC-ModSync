# 构建与测试

适用于需要自己构建产物或跑测试的人（OP / 二次开发者）。

---

## 1. 环境

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[dev]"                            # 运行时依赖 + pytest/pyyaml/pyinstaller
```

- 运行时依赖（仅 A 端）：boto3、paramiko、cryptography
- B 端单文件与 C 端运行时/兜底：**纯标准库**
- 测试：`pytest`（配置见 `pyproject.toml`，`testpaths=["tests"]`）

---

## 2. 构建 B 单文件（服务端执行器）

```bash
python tools/build_server.py            # 生成 server/mcmodsync-b.py
python tools/build_server.py --check    # 防漂移：仓库版本必须与重新生成一致
```

- 原理：AST 白名单拼接 `mcmodsync/` 中共享模块 + `server/b_main.py`
- 产物头部含 `# GENERATED, do not edit`，内容不含时间戳，可复现
- CI 会执行 `--check` 与「Python 3.8 语法检查」两步
- 部署：由 A 端 `push-server` 自动上传到 `server.remoteBPath`（升级时保留 `.bak`），亦可手工拷贝

---

## 3. 构建 C 端「纯 Python 兜底」单文件

```bash
python tools/build_client.py              # 生成 client/mcmodsync.py
python tools/build_client.py --check      # 防漂移
python tools/build_client.py --print-modules
```

- 原理：把 C 端依赖链（12 个纯标准库模块）打进**确定性 zip**，base64 内嵌进单个 `.py`
- 运行时自解压到临时目录后调用 CLI，系统 Python ≥ 3.10 可直接执行：
  `python mcmodsync.py sync --target "<整合包目录>"`
- `--check` 比对解压后各成员的 sha256（跨 zlib 版本稳健），CI 会执行

---

## 4. 打包 C 端分发包

```bash
mcmodsync package-client -c pack.local.json                  # 推荐（A 端 CLI）
# 等价于：
python tools/package_client.py [--out DIR] [--no-exe] [--exe PATH] [--skip-verify]
```

产物 `dist/client-package/`：

```
更新mod.bat             [12.1] 原文（CRLF）
更新mod.sh              [12.2] 原文（LF）
_updater/mcmodsync.exe  PyInstaller 单文件（Linux 为 mcmodsync-linux）
_updater/mcmodsync.py   纯 Python 兜底
_updater/config.json    [3.6]，由 pack.local.json 渲染
SHA256SUMS.txt          各文件 sha256（sha256sum 格式，按路径排序）
```

要点：

- PyInstaller 配置在 `packaging/mcmodsync.spec`（入口 `packaging/entry_client.py`，绝对导入）
- `excludes` 显式排除 boto3/botocore/paramiko/cryptography 及传递依赖，以及 tkinter/pytest/numpy 等
- `upx=False`：压缩壳是常见杀软误报来源（关联分支 B-02）
- 组装时会做**产物核验**：读取 exe 内嵌 PYZ 统计模块名，若检出应排除模块则退出码 1
- 校验和本地复核：
  ```bash
  cd dist/client-package && sha256sum -c SHA256SUMS.txt     # Windows: certutil / Get-FileHash
  ```
- 分发：把整个目录给玩家，覆盖到整合包根目录（与 `_updater/` 同级）

## 5. 测试

```bash
python -m pytest                      # 全量（联网用例默认跳过）
MCMS_LIVE=1 python -m pytest          # 含联网用例（对象存储/SSH/Modrinth/CurseForge）
MCMS_LIVE=1 MCMS_CF_KEY=<key> python -m pytest tests/test_provider_curseforge.py -k live
```

**测试文件一览**

| 文件 | 覆盖 |
|---|---|
| `test_hashing/paths/planner/locking/canonicaljson_sign/ed25519_min/signing` | 共享模块与签名（含 RFC 8032 官方向量） |
| `test_stdlib_purity` | 纯标准库性 + Python 3.8 语法兼容 |
| `test_build/test_b_apply/test_b_rollback` | 单文件 B：构建防漂移、13 步 apply、9 步 rollback、错误码 |
| `test_pusher` | A 端推送/回滚全流程（LocalConn 替身 + 真实主机联网） |
| `test_publisher_minio` | 发布流程（累计 delete、blob 去重、云端恢复、真机七彩云） |
| `test_provider_modrinth/curseforge` | mod 平台 provider（mock + 真机） |
| `test_fetcher` / `test_cli` | 编排/manual 闭环/CLI 分发与校验 |
| `test_client` | C 端 15 步 sync / verify / rollback / doctor（TL-5 全条目） |
| `test_client_main` / `test_entries` | C 端打包入口、进度条与日志；入口脚本（真实 sh / cmd 执行） |
| `test_packaged_client` | 分发包结构、SHA256SUMS、exe 内模块、双击链路端到端 |

**测试夹具**

- `tests/bharness.py`：B 端子进程驱动 + 单文件构建产物路径
- `tests/charness.py`：本地 `ThreadingHTTPServer` 对象存储替身 + Ed25519 签名发布 + 实例目录构造
- `tests/fixtures/` 有意留空（夹具全部动态生成）

> 联网用例对网络瞬态敏感（曾出现单次失败、复跑通过）；离线用例不受影响。

## 6. 故障注入（仅测试用）

**C 端**（环境变量，三个注入点）：

```bash
MCMODSYNC_FAULT=after-backup  # 备份并写 changes.json 之后、应用之前
MCMODSYNC_FAULT=mid-apply     # 应用进行到一半（按累计字节过半触发）
MCMODSYNC_FAULT=after-state   # 写完 state.json 之后
# 注入后退出码 99；再次运行（不带该变量）必须收敛到目标状态
python tools/... # 或
MCMODSYNC_FAULT=mid-apply mcmodsync.exe sync --target "<整合包目录>"
```

**B 端**（子命令参数）：

```bash
python server/mcmodsync-b.py apply  --server-dir ... --desired ... --inject-fault after-backup
python server/mcmodsync-b.py rollback --server-dir ... --inject-fault after-backup
```

⚠️ 注入点为显式分支，**生产代码不得使用**；CI 用它们验证「崩溃后可重跑收敛」。

## 7. CI

`.github/workflows/ci.yml` 两个作业：

| 作业 | 内容 |
|---|---|
| `test`（ubuntu，Python 3.10/3.12） | 安装 → B 单文件防漂移 → B 单文件 3.8 语法 → C 端依赖检查（`tools/check_c_deps.py`）→ C 端单文件兜底防漂移 → `pytest` |
| `windows-c`（windows-latest，Python 3.12） | 生成兜底单文件 → 组装分发包（构建 exe + 渲染 config + SHA256SUMS + 产物核验）→ C 端测试（含真实 `更新mod.bat` 双击链路、路径含空格/中文）→ 上传 `client-package` 工件 |

`tools/check_c_deps.py` 的三重判定：顶层 import 无第三方 / 函数内惰性引用记 WARN（由 `.spec excludes` 兜住）/
**屏蔽第三方库的子进程内仍能加载并运行 C 端入口**。

## 8. 发布前检查清单

- [ ] `python -m pytest` 全绿
- [ ] `python tools/build_server.py --check` OK（若改了共享模块或 `b_main.py`）
- [ ] `python tools/build_client.py --check` OK（若改了 C 端模块，**必须先重新生成**）
- [ ] `python tools/check_c_deps.py` rc=0
- [ ] 分发包 `SHA256SUMS.txt` 与文件一致；exe 产物核验通过
- [ ] `dist/`、`build/`、`pack.local.json`、`ssh.json` 未入库
