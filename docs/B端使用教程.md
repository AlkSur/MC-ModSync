# B端使用教程（MC 服务器侧）

B 是住在 MC 服务器上的一个小脚本 `mcmodsync-b.py`。你只需要知道三件事：

1. **它不常驻、不占内存**。平时它不运行，只有 OP 推送或回滚时被远程叫起来干一次活。
2. **你基本不用碰它**。OP 端的命令会自动上传、升级、调用它。
3. **重启服务器永远是你手动做的**。脚本不替你重启，因为启动成不成功只有你亲眼确认才算数。

## 〇、你需要哪些文件

B 端**只有一个文件**：

```
mcmodsync-b.py          ← B 脚本本体（单文件，纯 Python 标准库，兼容 Python 3.8+）
```

| 项 | 说明 |
| --- | --- |
| 需要你配置什么 | **什么都不用配**。服务器地址、目录、保留份数都由 OP 端推送时传参进来 |
| 需要装什么依赖 | **不需要**。只用 Python 标准库，服务器自带的 `python3` 就能跑 |
| 需要常驻运行吗 | **不需要**。平时不运行，被 OP 远程调用时才起来干一次活 |

**通常你不用手工部署它**：OP 执行 `mcmodsync push-server` 时会自动把 B 上传到服务器（路径见 `pack.local.json` 的 `server.remoteBPath`，默认 `/www/mcmodsync-b.py`），并在协议版本变化时自动升级、留 `.bak` 备份。

只有两种情况需要你手工放：

1. 服务器**没有** `python3`（先装：`apt install python3` 或 `yum install python3`，无需 pip）
2. OP 端的 SSH 账号没有写 `/www` 的权限——这时候把文件放进有权限的目录，让 OP 改配置里的 `remoteBPath` 指过去

手工放置就是**把这一个文件复制到服务器**，例如：

```
scp mcmodsync-b.py root@你的服务器:/www/mcmodsync-b.py
```

不需要建任何目录、不需要改文件内容——它自己会创建 `.mcmodsync/`、`.mcmodsync-staging/`、history 目录。

### 手上没有现成压缩包？两种办法

**办法一：从源码仓库自己出包**

在仓库根目录执行：

```
python tools\make_release.py
```

生成 `dist\release\MC-ModSync-B端-服务端脚本-v2.0.0.zip`，解压即用。

**办法二：直接从仓库里挑出这一个文件（B 端就是单文件）**

```
<仓库根>\server\mcmodsync-b.py     ← 复制它到服务器即可，其余文件和 B 端无关
```

不需要带 `mcmodsync\`、`tools\`、`client\` 等目录——B 端只用这一个文件，且不依赖任何第三方库（服务器自带的 Python 3.8+ 就能跑）。

验证服务器上能否运行：

```bash
python3 mcmodsync-b.py --help
```

## 一、服务器上多了哪些东西

| 位置 | 是什么 |
| --- | --- |
| `/www/mcmodsync-b.py`（默认路径） | B 脚本本体 |
| `mcmodsync-b.py.bak` | 旧版本备份，升级时自动留的 |
| `<服务器目录>/.mcmodsync/` | 状态文件 + 日志（`logs/` 子目录） |
| `<服务器目录>/.mcmodsync-staging/` | 推送中的临时区，干完活自动清空 |
| `/www/mcmodsync-history/`（默认路径） | 每次变更的完整备份（默认保留最近 3 次） |

这些都不需要你手工维护。

## 二、你唯一要做的操作：重启并看日志

OP 每次推送后会告诉你"重启一下服务器"。你照常重启，然后看日志：

- 出现 `Done (` → 告诉 OP"成功了"，他会去发布客户端。
- 报错 / 崩了 → 告诉 OP"起不来"，他会执行回滚，你再重启一次确认恢复。

## 三、出问题时去哪看

- **B 的日志**：`<服务器目录>/.mcmodsync/logs/` 下面，按子命令和版本号命名，排障先看最新一个。
- **回滚后被保全的手工改动**：如果你手动改过 mods 里的文件，回滚时旧文件不会直接被覆盖，而是被挪到 `history/<packId>/<版本>/rollback-drift/` 里，可以去那找回来。

## 四、日常维护（可选）

- **磁盘**：history 默认保留 3 份备份。`df -h` 定期看一眼；空间紧张就让 OP 把 `historyKeep` 调小。
- **升级 B**：不用管，OP 推送时会自动检测版本并升级，旧版留 `.bak` 兜底。
- **回滚 B 本体**：万一是新版 B 脚本本身出问题，把 `mcmodsync-b.py.bak` 改回 `mcmodsync-b.py` 即可。

## 五、安全提醒

- B 脚本里**不含任何密码和密钥**，它只是个干活的工具。
- 服务器建议只用 SSH 密钥登录，关闭密码登录。
- 不要手工删 `.mcmodsync/` 和 history 目录——删了备份就没法回滚了。
